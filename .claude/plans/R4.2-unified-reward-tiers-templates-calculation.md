# R4.2 — Unified: KPI Templates, Reward Tiers & Calculation Engine
# ═══════════════════════════════════════════════════════════════════════════════

## Overview

**Replaces:** R4.2a (Reward Policies & Categories) + R4.2b (Calculation Engine & Disbursement)

**Architecture:** Instead of 5 standalone reward policy tables, embed reward tier
configuration directly as JSON on `KpiContributorConfig.rewardTiers`. One KPI page
configures everything: fields, roles, stages, credit mode, reward tiers, and benefits.

**Key insight:** Real university policies define fixed per-role amounts
("First Author: ₹50,000, Co-Author: ₹10,000 each"), not "split pool by credit%".
The config structure reflects this reality.

---

## Locked Decisions

| # | Decision |
|---|----------|
| D1 | Reward tiers are **embedded JSON** on `KpiContributorConfig`, NOT separate tables |
| D2 | `KpiTemplate` is a new model for pre-built template bundles (form + roles + tiers) |
| D3 | `ContributorReward` is the **only new table** — stores calculated/disbursed payouts |
| D4 | Tier qualification: `AUTO` (rules against form data) or `MANUAL` (user picks dropdown) |
| D5 | Three distribution modes: `SPLIT_BY_CREDIT`, `FULL_TO_EACH`, `LEAD_ONLY` |
| D6 | Tier progression: `ADDITIVE`, `DIFFERENTIAL`, `REPLACEMENT` — for multi-tier KPIs |
| D7 | Rewards auto-calculate on verification, but require explicit approval before disbursement |
| D8 | All reward amounts reference existing `BenefitType` catalog (MONETARY, CREDIT_HOURS, etc.) |
| D9 | External contributors with `isExcludedFromReward=true` are skipped during calculation |
| D10 | Reward calculation is non-blocking — if it fails, verification still succeeds |
| D11 | KPI copy (all 3 modes) carries rewardTiers config as part of KpiContributorConfig |

model KpiTemplate {
  id                 String   @id @default(cuid())

export const rewardCalcMethodSchema = z.enum([
  "FIXED",            // Fixed amount regardless of score
  "PERCENTAGE",       // Percentage of a base value (VALUE_FIELD)

  "SPLIT_BY_CREDIT",  // Pool amount × creditPercent / 100
  "FULL_TO_EACH",     // Each eligible contributor gets the full amount
  "LEAD_ONLY",        // Only default-role contributor gets it

  "ADDITIVE",         // Stack rewards from all qualifying tiers
  "DIFFERENTIAL",     // Pay difference between current and previous tier
  "REPLACEMENT",      // Highest qualifying tier replaces all lower
]);

export const tierQualificationModeSchema = z.enum([
  "AUTO",   // System evaluates rules against form data
  "MANUAL", // User selects tier from dropdown when recording achievement
]);

export const tierRuleOperatorSchema = z.enum([
  "eq", "neq", "contains", "not_contains",
  "gte", "lte", "gt", "lt",
  "in", "not_in",
]);

export const tierRuleSchema = z.object({
  fieldKey: z.string(),            // Must reference a field in achievementFormConfig
  operator: tierRuleOperatorSchema,
  value: z.unknown(),              // String, number, or array for "in"

  benefitTypeCode: z.string(),     // Must match BenefitType.code
  calcMethod: rewardCalcMethodSchema,
  amount: z.number().min(0),       // Base amount (₹50000, 5%, 1000/unit, etc.)

  contributorRoleCode: z.string(), // Must match ContributorRole.code

### Phase 3: Reward Tier Resolution Engine (Day 2)

**New file:** `src/lib/kra-kpi/reward-tier-resolver.ts`

**Functions:**

```typescript
// Resolve which tier(s) an achievement qualifies for
export function resolveTiers(
  rewardTierConfig: RewardTierConfig,
  achievementFormData: Record<string, unknown> | null,
  manualTierCode?: string,
): ResolvedTier[]

interface ResolvedTier {
  tier: RewardTier;
  matchedBy: "AUTO" | "MANUAL";
  ruleResults?: Array<{ fieldKey: string; passed: boolean; actual: unknown; expected: unknown }>;
}
```

**Resolution logic:**

```
1. If manualTierCode is provided:
   → Return [tier where code === manualTierCode] with matchedBy="MANUAL"

2. For AUTO tiers:
   → For each active tier (sorted by sortOrder):
     → Evaluate all rules against achievementFormData
     → A tier qualifies if ALL rules pass (AND logic)
   → Collect all qualifying tiers

3. Apply tierProgression:
   - REPLACEMENT: Keep only the highest-sortOrder qualifying tier
   - ADDITIVE: Keep all qualifying tiers
   - DIFFERENTIAL: Keep all, but mark previous tiers for differential calc

4. Return resolved tiers
```

**Rule evaluation:**

```typescript
function evaluateRule(rule: TierRule, formData: Record<string, unknown>): boolean {
  const actual = formData[rule.fieldKey];
  if (actual === undefined || actual === null) return false;

  switch (rule.operator) {
    case "eq": return actual === rule.value;
    case "neq": return actual !== rule.value;
    case "contains": return String(actual).includes(String(rule.value));
    case "gte": return Number(actual) >= Number(rule.value);
    case "lte": return Number(actual) <= Number(rule.value);
    case "gt": return Number(actual) > Number(rule.value);
    case "lt": return Number(actual) < Number(rule.value);
    case "in": return Array.isArray(rule.value) && rule.value.includes(actual);
    case "not_in": return Array.isArray(rule.value) && !rule.value.includes(actual);
    case "not_contains": return !String(actual).includes(String(rule.value));
    default: return false;
  }
}
```

### Phase 4: Reward Calculation Engine (Day 2-3)

**New file:** `src/lib/kra-kpi/reward-calculation-engine.ts`

**Main function:**

```typescript
export async function calculateRewardsForAchievement(
  achievementId: string,
  tenantId: string,
): Promise<{ rewards: CalculatedReward[]; tierCode: string; tierAutoMatched: boolean } | null>

interface CalculatedReward {
  contributorId: string;
  userId: string | null;
  benefitTypeCode: string;
  tierCode: string;
  calcMethod: string;
  baseAmount: number;
  calculatedAmount: number;
  creditPercent: number;
  distributionMode: string;
}
```

**Calculation flow:**

```
1. Load achievement with:
   - contributors (with roles)
   - kpiDefinition → contributorConfig (with rewardTiers)
   - achievementFormData

2. If no rewardTiers configured → return null (no rewards for this KPI)

3. Resolve qualifying tiers via resolveTiers()
   - If no tiers qualify → return null

4. For each resolved tier:
   a. Find roleRewards matching each contributor's role
   b. Filter out:
      - Contributors with isExcludedFromReward = true
      - EXTERNAL contributors if tier.externalPolicy = "EXCLUDE"
   c. For each eligible contributor × benefit:
      - Calculate amount based on calcMethod:
        - FIXED: amount as-is
        - PERCENTAGE: amount/100 × VALUE_FIELD value from formData
        - PER_UNIT: amount × UNIT_FIELD value from formData
        - SCORE_MULTIPLIED: amount × achievement.effectiveScore
      - Apply distributionMode:
        - FULL_TO_EACH: each gets calculatedAmount
        - SPLIT_BY_CREDIT: calculatedAmount × creditPercent / 100
        - LEAD_ONLY: only contributors whose role isDefault get it
      - Apply cap if configured
      - Apply maxPersons limit (by sortOrder of contributors)
   d. Handle tierProgression:
      - ADDITIVE: sum all tier rewards
      - DIFFERENTIAL: tier[n] reward - tier[n-1] reward
      - REPLACEMENT: only highest tier rewards

5. Return calculated rewards + tier info
```

**Persistence function (called on verification):**

```typescript
export async function persistRewards(
  tenantId: string,
  achievementId: string,
  rewards: CalculatedReward[],
  tierCode: string,
  tierAutoMatched: boolean,
): Promise<void>
```

- Creates `ContributorReward` rows with status="CALCULATED"
- Updates `Achievement.rewardTierCode` and `Achievement.rewardTierAutoMatched`
- All in a transaction
