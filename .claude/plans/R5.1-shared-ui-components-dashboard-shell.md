# R5.1 — Shared UI Component Library + Dashboard Shell

**Assigned to**: Opus (UI/UX-heavy)
**Depends on**: R5.0 (scope resolver must exist)
**Blocks**: R5.2–R5.6 (all dashboard tabs use these components)

---

## Why This Exists

Every dashboard tab reuses the same building blocks: data tables, score badges, charts, slide-overs, filter bars. Building these FIRST as a shared library ensures visual consistency, reduces code duplication, and enforces UX principles across all modules. This sub-module also creates the dashboard page shell with persona-aware tab navigation.

---

## UX Rules (Non-Negotiable for Every Component)

Reference the full UX-1 through UX-10 principles in the master plan (`fluffy-skipping-bird.md`). Key rules for this sub-module:

| Rule | Summary |
|------|---------|
| **UX-3** | 5-color system only: teal (#0f766e), blue (#2563eb), amber (#f59e0b), rose (#dc2626), slate (#64748b) |
| **UX-6** | Skeleton loaders for data fetch, never blank screens or raw spinners |
| **UX-7** | Focus rings, aria-labels, color+text pairing, keyboard nav |
| **UX-8** | Desktop/tablet/mobile responsive breakpoints at 1024px and 768px |
| **UX-10** | Charts: max 6 series, label axes, tooltips, "View as table" fallback |

## Task 1: Shared Components — `src/components/dashboard/shared/`

Build each component as a standalone file. Use existing Tailwind design tokens (`--brand`, `--accent`, `--danger`, `--background`, `--foreground`).

### 1a. `metric-card.tsx` — `<MetricCard>`
```typescript
type MetricCardProps = {
  label: string;              // "Allocations", "Avg Score"
  value: string | number;     // "45", "72.3%"
  tone?: 'brand' | 'blue' | 'amber' | 'rose' | 'slate'; // default: 'brand'
  trend?: { direction: 'up' | 'down' | 'flat'; label: string }; // optional: "↑ 12% vs last period"
  loading?: boolean;          // shows SkeletonCard variant='metric'
  icon?: React.ReactNode;     // optional Lucide icon
};
```
- Value uses `text-3xl font-bold font-mono`
- Label uses `text-xs uppercase tracking-wide text-muted`
- Card uses existing `glass-panel` pattern (backdrop blur + border)
- When `loading=true`, render a skeleton rectangle matching the card dimensions
- Tone sets the left border color (4px left border)

### 1b. `score-badge.tsx` — `<ScoreBadge>`
```typescript
type ScoreBadgeProps = {
  score: number;     // 0–100
  size?: 'sm' | 'md'; // default 'md'
};
```
- Auto-color: ≥80 → teal, ≥50 → blue, ≥25 → amber, <25 → rose, null/undefined → slate
- Shows the number AND the color (UX-7: never color-only)
- Rounded pill shape: `rounded-full px-2 py-0.5 text-xs font-medium`
- Background uses color at 10% opacity, text uses full color

### 1c. `completion-bar.tsx` — `<CompletionBar>`
```typescript
type CompletionBarProps = {
  percent: number;     // 0–100
  showLabel?: boolean; // default true — shows "72%" text
  height?: 'sm' | 'md'; // default 'sm' (4px vs 8px)
};
```
- Bar background: `bg-slate-200 rounded-full`
- Fill color: same auto-color logic as ScoreBadge
- Label positioned at end of bar or right-aligned
- Zero state: empty bar with "0%" label

### 1d. `status-pill.tsx` — `<StatusPill>`
```typescript
type StatusPillProps = {
  state: string; // raw enum value from API
};
```
- Mapping (exact, case-insensitive):
  - DRAFT → amber, label "Draft"
  - SUBMITTED → blue, label "Submitted"
  - RECOMMENDED → blue, label "Recommended"
  - VERIFIED → teal, label "Verified"
  - REJECTED → rose, label "Rejected"
  - PENDING → amber, label "Pending"
  - RELEASED → teal, label "Released"
  - REVOKED → rose, label "Revoked"
  - IN_PROGRESS → blue, label "In Progress"
  - COMPLETED → teal, label "Completed"
  - Unknown → slate, label = raw value
- Same pill styling as ScoreBadge (rounded-full, colored bg + text)

### 1e. `skeleton-card.tsx` — `<SkeletonCard>`
```typescript
type SkeletonCardProps = {
  variant: 'metric' | 'table-row' | 'chart';
  count?: number; // how many to render (default 1)
};
```
- `metric`: rectangle matching MetricCard dimensions, animated pulse
- `table-row`: horizontal bars with varying widths, animated pulse
- `chart`: area/rectangle shape 200px tall, animated pulse
- Use Tailwind `animate-pulse bg-slate-200 rounded`

### 1f. `empty-state.tsx` — `<EmptyState>`
```typescript
type EmptyStateProps = {
  icon?: React.ReactNode;    // Lucide icon
  title: string;             // "No achievements yet"
  description: string;       // "KPIs are allocated — submissions can begin."
  actionLabel?: string;      // "Go to My KPIs"
  onAction?: () => void;
};
```
- Centered vertically in its container
- Icon at 48px, muted color
- Title: `text-lg font-semibold`
- Description: `text-sm text-muted`
- Action button: standard branded button
- Minimum height: 200px

### 1g. `data-table.tsx` — `<DataTable>` (most complex component)
```typescript
type DataTableProps<T> = {
  columns: ColumnDef<T>[];           // TanStack column definitions
  data: T[];
  loading?: boolean;                  // shows skeleton rows
  emptyState?: { title: string; description: string };
  sortable?: boolean;                 // default true
  pagination?: { pageSize: number };  // default { pageSize: 10 }
  onRowClick?: (row: T) => void;      // optional row click handler
  rowClassName?: (row: T) => string;  // optional per-row styling
  mobileCardRenderer?: (row: T) => React.ReactNode; // card layout for mobile
};
```
- Wraps TanStack React Table with `getCoreRowModel`, `getSortedRowModel`, `getPaginationRowModel`
- **Sorting**: Click column header to sort. Shows ▲/▼ indicator. Multi-column sort NOT needed.
- **Pagination**: Bottom bar with "Showing 1–10 of 45" + Previous/Next buttons + page size selector (10/25/50)
- **Loading**: When `loading=true`, show `count` skeleton rows (default 5)
- **Empty**: When `data.length === 0` and not loading, show `<EmptyState>` with provided props
- **Mobile** (<768px): If `mobileCardRenderer` is provided, switch from table to card list. Each row becomes a card rendered by the custom function. If not provided, table scrolls horizontally.
- **Row click**: If `onRowClick` provided, rows have `cursor-pointer` and hover highlight
- **Accessibility**: `<th scope="col">`, proper `<thead>/<tbody>`, keyboard-navigable rows (Tab + Enter)
- **Row hover**: subtle `hover:bg-slate-50` highlight

### 1h. `filter-bar.tsx` — `<FilterBar>`
```typescript
type FilterDef = {
  key: string;
  label: string;
  type: 'select' | 'multi-select' | 'date-range';
  options?: { value: string; label: string }[];  // for select/multi-select
};
type FilterBarProps = {
  filters: FilterDef[];
  active: Record<string, any>;       // current filter values
  onChange: (key: string, value: any) => void;
  onClear: () => void;               // clear all
};
```
- Renders filter controls in a horizontal row (wraps on mobile)
- Below the controls: active filters as pills with ✕ button to remove each
- "Clear all" link at end of pill row (only visible when filters active)
- Select/multi-select: styled dropdown (native `<select>` or custom if needed)
- Date range: two date inputs (from/to)

### 1i. `slide-over.tsx` — `<SlideOver>`
```typescript
type SlideOverProps = {
  open: boolean;
  onClose: () => void;
  title: string;
  subtitle?: string;
  children: React.ReactNode;
  width?: 'md' | 'lg';  // md=480px, lg=640px (desktop). Full-width on mobile.
};
```
- Slides in from right edge
- Semi-transparent backdrop (click to close)
- Escape key closes
- Focus trap: Tab cycles within the panel while open
- Header: title + subtitle + close (✕) button
- Body: scrollable content area
- Transition: `transform translate-x` animation (300ms ease)

### 1j. `confirm-dialog.tsx` — `<ConfirmDialog>`
```typescript
type ConfirmDialogProps = {
  open: boolean;
  title: string;
  description: string;      // "Release 5 rewards totaling ₹42,000?"
  confirmLabel: string;      // "Release"
  onConfirm: () => void;
  onCancel: () => void;
  variant?: 'danger' | 'warning' | 'default'; // default='default'
  loading?: boolean;         // shows spinner on confirm button
};
```
- Centered modal with backdrop
- `variant='danger'` → red confirm button
- `variant='warning'` → amber confirm button
- Cancel button always secondary/outline
- Escape key cancels
- When `loading=true`, confirm button shows spinner and is disabled

### 1k. `period-selector.tsx` — `<PeriodSelector>`
```typescript
type PeriodSelectorProps = {
  periods: { id: string; name: string; startDate: string; endDate: string; state: string }[];
  selectedId: string | null;
  onChange: (periodId: string) => void;
};
```
- Dropdown showing period name + date range
- Defaults to the period where `state = 'IN_PROGRESS'` or `'OPEN'` (current active)
- If no active period, defaults to most recent
- Compact styling for sticky header placement

### 1l. `breadcrumb.tsx` — `<Breadcrumb>`
```typescript
type BreadcrumbItem = { label: string; onClick?: () => void };
type BreadcrumbProps = { items: BreadcrumbItem[] };
```
- Items separated by `>`
- Last item: bold, no click handler (current location)
- All others: clickable links with hover underline
- Mobile: if >3 items, show `first > ... > last two` (truncate middle)

### 1m. `chart-container.tsx` — `<ChartContainer>`
```typescript
type ChartContainerProps = {
  title: string;
  children: React.ReactNode;   // Recharts component
  fallbackData?: { headers: string[]; rows: (string | number)[][] }; // for "View as table"
  loading?: boolean;
};
```
- Header with title (left) and "View as table" toggle link (right)
- When toggled, hides chart and shows a simple HTML table with the fallback data
- Loading: shows SkeletonCard variant='chart'
- Min-height: 200px, max-height: 400px
- Responsive: on mobile, chart height reduces to 160px

### 1n. `orientation-banner.tsx` — `<OrientationBanner>`
```typescript
type OrientationBannerProps = {
  storageKey: string;         // e.g., "dashboard-welcome"

```
- Info-toned banner (blue-50 bg, blue border)

- Never shows again after dismissed
- Shows on first visit only

### 1o. `export-button.tsx` — `<ExportButton>`
```typescript
type ExportButtonProps = {
  label?: string;     // default "Export CSV"

```

- When loading, icon becomes spinner

## Task 2: Dashboard Page Shell

### 2a. Create page: `src/app/dashboard/page.tsx`

Server component:
1. Get session user (use existing auth pattern from other pages)
2. Import `resolveUserDashboardScope` from `src/lib/org-structure/scope-resolver.ts`
3. Call `resolveUserDashboardScope(tenantId, userId)`
4. Import and render `<DashboardHub scope={scope} />`

### 2b. Create: `src/components/dashboard/dashboard-hub.tsx`

Client component (`'use client'`). This is the main container.

**Props**:
```typescript
type DashboardHubProps = {
  scope: UserDashboardScope;
};
```

**State**:
- `activeTab` — read from URL param `?tab=` (default: `'my-kpis'`)
- `selectedPeriodId` — shared across all tabs

**Tab visibility logic** (based on scope, no new role concepts):
| Tab Key | Label | Show When |
|---------|-------|-----------|
| `my-kpis` | My KPIs | Always |
| `reviews` | My Reviews | `scope.headOfUnits.length > 0` |
| `unit` | My Unit | `scope.headOfUnits.length > 0` |
| `org` | Organization | `scope.headOfUnits.length > 0` AND any headOfUnit has children, OR `scope.isTenantAdmin` |
| `rewards` | Rewards | `scope.hasApprovalAuthority` OR `scope.isTenantAdmin` |
| `notifications` | Notifications | Always |

**Tab badges** (actionable counts):
- Reviews tab: show pending count badge (fetch from API on mount)
- Notifications tab: show unread count badge (use existing `getUnreadCount()`)

**Layout**:
```
┌──────────────────────────────────────────────────┐
│ KPI Dashboard                    [Period: 2025-26]│
│                                                   │
│ [My KPIs] [My Reviews (7)] [My Unit] [Org] [Rew] │
│ ─────────────────────────────────────────────────│
│                                                   │
│  (active tab content rendered here)               │
│                                                   │
└──────────────────────────────────────────────────┘
```

- PeriodSelector in top-right, sticky
- Tab bar below header
- Active tab has bottom border highlight (brand color)
- Tab content area below with padding
- OrientationBanner at top of content area (first visit only)

**URL state management**:
- Use `useSearchParams()` from Next.js
- Tab: `?tab=my-kpis`
- Period: `?periodId=xxx`
- Other params passed to child tabs: `?unitId=xxx&view=children`

### 2c. Create: `src/app/api/tenant/kra-kpi/dashboard/scope/route.ts`

GET endpoint:
1. Authenticate user
2. Call `resolveUserDashboardScope(tenantId, userId)`
3. Return the `UserDashboardScope` object as JSON

This is used by the client-side dashboard hub to determine tab visibility without SSR.
