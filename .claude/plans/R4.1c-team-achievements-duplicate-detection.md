# R4.1c — Team Achievements & Duplicate Detection
# ═══════════════════════════════════════════════════════════════════════════════

## Goal

Enable **multi-contributor achievement recording** — reporter adds internal (by UID/name)
and external contributors with roles and credit splits. Add **duplicate detection** at
submission/verification using fields marked UNIQUE_CHECK. Migrate from inline
`contributionRole`/`creditPercent` to the new `AchievementContributor` model.

Depends on: R4.1a (ContributorRole, KpiApplicableRole), R4.1b (ExternalContributorTemplate, KpiContributorConfig)

---

## Locked Decisions

| # | Decision |
|---|----------|
| D1 | Reporter adds all contributors. Verifier validates the list. No consent flow. |
| D2 | One internal user appears at most once per achievement (@@unique on achievementId+userId) |
| D3 | External contributors: data validated against KPI's linked template |
| D4 | Credit sum enforced per KPI's `creditSumMode` (MUST_EQUAL_100, MAX_100, UNCAPPED) |
| D5 | Reporter auto-added as sole 100% contributor if no explicit list provided |
| D6 | Duplicate detection: exact match on UNIQUE_CHECK fields, fuzzy title+year as secondary |
| D7 | Duplicate result stored on achievement, shown to verifier as warning (not auto-block) |
| D8 | External contributors default to `isExcludedFromReward = true` |
| D9 | Cross-department attribution: each contributor's department gets proportional credit |
| D10 | **Deferred from R4.1a**: ContributorRole archive check must be updated — currently blocks archive when role is linked to KpiApplicableRole; should instead block only when role is used in AchievementContributor records. Auto-remove from KPI applicable lists on archive, block only if achievements reference it. |

## Schema (1 new model)

### AchievementContributor
```prisma
model AchievementContributor {
  id                    String                    @id @default(cuid())
  achievementId         String
  type                  ContributorType           @default(INTERNAL)
  // Internal
  userId                String?
  // External
  externalName          String?
  externalAffiliation   String?
  externalScope         ExternalContributorScope?
  externalData          Json?                     // validated against template
  // Common
  contributorRoleId     String
  creditPercent         Float
  isExcludedFromReward  Boolean                   @default(false)
  rewardRedistribution  String?                   // "RETURN_TO_POOL" | "SPLIT_INTERNAL" | "NO_REDISTRIBUTION"
  note                  String?
  addedByUserId         String
  createdAt             DateTime                  @default(now())
  updatedAt             DateTime                  @updatedAt
  achievement           Achievement               @relation(fields: [achievementId], references: [id], onDelete: Cascade)
  user                  User?                     @relation("ContributorUser", fields: [userId], references: [id])
  contributorRole       ContributorRole           @relation(fields: [contributorRoleId], references: [id], onDelete: Restrict)
  addedBy               User                      @relation("ContributorAddedBy", fields: [addedByUserId], references: [id])

  @@unique([achievementId, userId])
  @@index([achievementId])
  @@index([userId])
}
```

### `duplicate-detection-service.ts` (NEW)

```typescript
checkForDuplicates(kpiId, tenantId, formData: Record<string, unknown>): Promise<DuplicateCheckResult>
// 1. Get KPI's achievementFormConfig
// 2. Find fields with marker: "UNIQUE_CHECK"
// 3. For each UNIQUE_CHECK field with a value in formData:
//    - Query existing achievements for same KPI + tenant where formData[field] matches
//    - Exclude DRAFT state achievements
// 4. Secondary: fuzzy match on title + year (if title field exists)
// 5. Return: { hasDuplicates, matches: [{achievementId, matchedField, matchedValue, reportedByName, state}] }

type DuplicateCheckResult = {
  hasDuplicates: boolean;
  matches: Array<{
    achievementId: string;
    matchedField: string;
    matchedValue: string;
    reportedByName: string;
    achievementState: string;
    similarity: "EXACT" | "FUZZY";
  }>;
};
```

## Migration from Inline Fields

```typescript
// Migration script (run once):
async function migrateInlineContributors() {
  // 1. Find all achievements with contributionRole set
  const achievements = await prisma.achievement.findMany({
    where: { contributionRole: { not: null } },
    select: { id: true, reportedByUserId: true, contributionRole: true, creditPercent: true,
              kpiDefinition: { select: { id: true, tenantId: true, contributionRoles: true } } },
  });

  for (const ach of achievements) {
    // 2. Find or create ContributorRole matching the inline role name
    const role = await findOrCreateRole(ach.kpiDefinition.tenantId, ach.contributionRole);

    // 3. Create AchievementContributor
    await prisma.achievementContributor.create({
      data: {
        achievementId: ach.id,
        type: "INTERNAL",
        userId: ach.reportedByUserId,
        contributorRoleId: role.id,
        creditPercent: ach.creditPercent ?? 100,
        addedByUserId: ach.reportedByUserId,
      },
    });
  }

  // 4. For achievements WITHOUT contributionRole, add reporter as 100% default
}
```

## Validation Rules

- INTERNAL: `userId` required, must exist in same tenant
- EXTERNAL: `externalName` + `externalAffiliation` required
- EXTERNAL: `externalData` validated against KPI's linked ExternalContributorTemplate
- EXTERNAL: `isExcludedFromReward` defaults to true
- Credit sum: enforced per `KpiContributorConfig.creditSumMode`
- Cannot add/remove/edit contributors when achievement is not in DRAFT state
- ContributorRole must be in KPI's `KpiApplicableRole` list
- Same internal userId cannot appear twice on same achievement
- Duplicate detection: non-blocking warning (verifier decides)
