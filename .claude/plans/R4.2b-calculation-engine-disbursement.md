# R4.2b — Calculation Engine & Disbursement
# ═══════════════════════════════════════════════════════════════════════════════

## Goal

Build the **auto-calculation engine** that triggers when an achievement is verified —
resolves the applicable reward policy, determines the category/tier, calculates benefit
amounts using the configured method, distributes among contributors per role splits,
handles external exclusions, and creates reward records. Add **disbursement status tracking**
and a **rewards dashboard** for admin oversight.

Depends on: R4.1a, R4.1b, R4.1c, R4.2a (all previous modules)

---

## Locked Decisions

| # | Decision |
|---|----------|
| D1 | Calculation auto-triggers on achievement state → VERIFIED |
| D2 | Policy version is **locked at verification time** — stored on reward records |
| D3 | External contributors excluded by default — their share handled per `rewardRedistribution` |
| D4 | Reward records are immutable after APPROVED — create new adjustment records for corrections |
| D5 | Disbursement is status tracking only — no payment integration (use existing finance system) |
| D6 | Stage-wise rewards supported: if KPI has stages, rewards can trigger per stage completion |
| D7 | Budget cap is a **dashboard warning**, not a hard block |
| D8 | Recalculation on state change: if achievement goes VERIFIED → REJECTED, rewards are CANCELLED |
| D9 | **Re-verification**: if achievement re-enters VERIFIED (resubmit flow), cancel old rewards first, then recalculate with current policy |
| D10 | **Policy expiry alert**: dashboard warns admin when policy expires within 30 days and has no successor scheduled |
| D11 | **Category progression**: engine respects policy's `categoryProgression` setting (ADDITIVE/REPLACEMENT/DIFFERENTIAL) for achievements that upgrade tiers |
| D12 | **Policy resolution date**: engine uses `KpiRewardPolicyLink.policyResolutionDate` to determine which timestamp resolves the policy version |

### `reward-calculation-engine.ts` (NEW) — Core engine

```typescript
// ── Main entry point — called after verifyAchievement ──
calculateRewards(achievementId, tenantId): Promise<Result>
  // Steps:
  // 1. Load achievement + contributors + form data + KPI definition
  // 2. Get effective policy for this KPI (via KpiRewardPolicyLink)
  //    - If no policy linked → skip (no rewards configured)
  // 3. Resolve category:
  //    - If AUTO: evaluate qualificationRules against formData
  //    - If achievement already has categoryId set (reporter picked): use that
  //    - If no match: skip (achievement doesn't qualify for any tier)
  // 4. For each benefit pool in the category:
  //    a. Check minScoreThreshold — skip if score below
  //    b. Calculate total pool amount using calcMethod:
  //       - FIXED → fixedAmount
  //       - PERCENTAGE → formData[VALUE_FIELD] × percentage, min(cap)
  //       - SLAB_PERCENTAGE → walkSlabs(formData[VALUE_FIELD], slabs), min(cap)
  //       - PER_UNIT → formData[UNIT_FIELD] × ratePerUnit, min(maxUnits × ratePerUnit)
  //       - SCORE_MULTIPLIED → fixedAmount × (achievementScore / 100)
  //       - TIERED_MULTIPLIER → fixedAmount × findMultiplier(score, tiers)
  //    c. Handle external exclusions:
  //       - Find excluded contributors
  //       - Calculate their would-be share
  //       - Based on rewardRedistribution: RETURN_TO_POOL, SPLIT_INTERNAL, NO_REDISTRIBUTION
  //    d. Distribute among eligible contributors per roleSplits:
  //       - For each role with contributors:
  //         - SPLIT_WITHIN: splitPercent / personCount
  //         - REPEAT_PER_PERSON: splitPercent per person (may exceed pool — cap at pool)
  //         - FIXED_PER_PERSON: fixedPerPersonAmount per person
  //    e. Create ContributorReward records (status=CALCULATED)
  // 5. Lock: store rewardPolicyId + categoryId on each reward record

// ── Individual calculation helpers ──
calculatePoolAmount(pool: CategoryBenefitPool, formData: Record<string, unknown>, score: number): number
evaluateSlabs(value: number, slabs: Slab[]): number
findTierMultiplier(score: number, tiers: TierMultiplier[]): number
distributePool(poolAmount: number, contributors: ContributorWithRole[], roleSplits: CategoryRoleSplit[], externalPolicy: string): DistributionResult[]

// ── Recalculation / cancellation ──
cancelRewardsForAchievement(achievementId, tenantId, reason: string): Promise<Result>
  // Sets all CALCULATED/PENDING_APPROVAL rewards to CANCELLED
  // Called when achievement is REJECTED after being VERIFIED (edge case)
```

## Validation Rules

- Cannot calculate rewards if no policy linked to KPI
- Cannot calculate if achievement score below pool's minScoreThreshold
- Pool amount calculation must use correct VALUE_FIELD/UNIT_FIELD from form data
- Split distribution must not exceed pool total (except REPEAT_PER_PERSON with cap)
- Status transitions enforced: CALCULATED → PENDING → APPROVED → DISBURSED
- Cannot approve/disburse CANCELLED rewards
- Adjustments create new record, original marked ADJUSTED
- Only TENANT_ADMIN/TENANT_OWNER can approve/disburse
- Budget cap is informational only — no hard block

## Calculation Engine — Detailed Algorithm

```typescript
// Pseudocode for the core calculation

async function calculateRewards(achievementId, tenantId) {
  const achievement = await loadAchievementWithContributors(achievementId);
  const kpi = achievement.kpiDefinition;
  const policy = await getEffectivePolicy(kpi.id, tenantId, achievement.verifiedAt);

  if (!policy) return { ok: true, message: "No reward policy configured" };

  // Resolve category
  const category = await resolveCategory(policy, achievement);
  if (!category) return { ok: true, message: "Achievement doesn't match any category" };

  const rewards: CreateRewardInput[] = [];

  for (const pool of category.benefitPools) {
    // Score threshold check
    if (pool.minScoreThreshold && achievement.computedScore < pool.minScoreThreshold) continue;

    // Calculate total pool amount
    const totalPool = calculatePoolAmount(pool, achievement.achievementFormData, achievement.computedScore);

    // Separate internal vs external contributors
    const allContributors = achievement.contributors;
    const eligible = allContributors.filter(c => {
      if (c.isExcludedFromReward) return false;
      if (pool.externalContributorPolicy === "EXCLUDE" && c.type === "EXTERNAL") return false;
      return true;
    });
    const excluded = allContributors.filter(c => !eligible.includes(c));

    // Calculate excluded share for redistribution
    let redistributableAmount = 0;
    for (const exc of excluded) {
      const roleSplit = category.roleSplits.find(s => s.contributorRoleId === exc.contributorRoleId);
      if (roleSplit) redistributableAmount += totalPool * (roleSplit.splitPercent / 100);
    }

    // Determine effective pool (with redistribution)
    let effectivePool = totalPool;
    const redistributionMode = excluded[0]?.rewardRedistribution ?? "RETURN_TO_POOL";
    if (redistributionMode === "RETURN_TO_POOL") {
      effectivePool = totalPool - redistributableAmount; // reduce pool
    } else if (redistributionMode === "SPLIT_INTERNAL") {
      effectivePool = totalPool; // full pool redistributed to internal
    } else {
      effectivePool = totalPool - redistributableAmount; // no redistribution, reduce
    }

    // Distribute to eligible contributors
    for (const roleSplit of category.roleSplits) {
      const roleContributors = eligible.filter(c => c.contributorRoleId === roleSplit.contributorRoleId);
      if (roleContributors.length === 0) continue;

      const rolePoolShare = effectivePool * (roleSplit.splitPercent / 100);

      for (const contrib of roleContributors) {
        let amount: number;
        switch (roleSplit.multiPersonStrategy) {
          case "SPLIT_WITHIN":
            amount = rolePoolShare / roleContributors.length;
            break;
          case "REPEAT_PER_PERSON":
            amount = Math.min(rolePoolShare, effectivePool); // each gets full share, capped
            break;
          case "FIXED_PER_PERSON":
            amount = roleSplit.fixedPerPersonAmount ?? 0;
            break;
        }

        rewards.push({
          achievementId, contributorId: contrib.id,
          benefitTypeId: pool.benefitTypeId,
          rewardPolicyId: policy.id, categoryId: category.id,
          calcMethod: pool.calcMethod,
          poolAmount: totalPool, calculatedAmount: amount,
          splitPercent: roleSplit.splitPercent,
          status: "CALCULATED",
        });
      }
    }
  }

  // Bulk create all reward records
  await prisma.contributorReward.createMany({ data: rewards });
  return { ok: true, data: { rewardCount: rewards.length } };
}
```

## Test Scenarios

### Auto-Calculation on Verification
- T1: Verify achievement with FIXED ₹50,000 pool, Lead(50%)+Co(20%)+Mentor(30%) → Lead gets ₹25K, Co gets ₹10K, Mentor gets ₹15K
- T2: Verify with no policy linked → no rewards created, no error
- T3: Achievement score below minScoreThreshold → reward skipped for that pool
- T4: Achievement matches Q1 category via AUTO qualification → Q1 pool used

### Calculation Methods
- T5: FIXED: pool=₹50,000 → total=₹50,000
- T6: PERCENTAGE: actualValue=₹25,00,000, rate=5%, cap=₹3,00,000 → total=min(₹1,25,000, ₹3,00,000)=₹1,25,000
- T7: PERCENTAGE with cap hit: actualValue=₹1,00,00,000, rate=5%, cap=₹3,00,000 → total=₹3,00,000
- T8: SLAB_PERCENTAGE: value=₹1,20,00,000, slabs=[{0-50L:5%},{50L-1Cr:3%},{1Cr+:2%}] → (50L×5%)+(50L×3%)+(20L×2%)=2.5L+1.5L+0.4L=₹4,40,000
- T9: PER_UNIT: 45 participants × ₹500/participant = ₹22,500
- T10: PER_UNIT with maxUnits: 45 participants, max=30, rate=₹500 → min(45,30)×500=₹15,000
- T11: SCORE_MULTIPLIED: base=₹10,000, score=85 → ₹8,500
- T12: TIERED_MULTIPLIER: base=₹10,000, score=92, tier[90-100]=1.5x → ₹15,000

### Multi-Person Strategies
- T13: SPLIT_WITHIN: 2 co-authors, pool share=20% of ₹50K=₹10K → each gets ₹5K
- T14: REPEAT_PER_PERSON: 2 co-authors, 20%=₹10K → each gets ₹10K (total ₹20K from pool)
- T15: FIXED_PER_PERSON: 2 co-authors, fixed=₹5K → each gets ₹5K regardless of pool

### External Contributor Handling
- T16: External contributor excluded (default) → no reward record created
- T17: RETURN_TO_POOL: external's 20% share reduces total pool → internal get from reduced pool
- T18: SPLIT_INTERNAL: external's 20% share redistributed proportionally to internal contributors
- T19: NO_REDISTRIBUTION: external's share simply gone → total disbursed < total pool

### Multiple Benefit Types
- T20: Category has Monetary ₹50K + Points 100 + Hours 3 → 3 reward records per contributor
- T21: minScoreThreshold differs per pool → some pools skip, others calculate

### Status Transitions
- T22: CALCULATED → PENDING_APPROVAL → success
- T23: PENDING_APPROVAL → APPROVED → success
- T24: APPROVED → DISBURSED with transactionRef → success
- T25: Any non-DISBURSED → CANCELLED → success
- T26: DISBURSED → CANCELLED → rejected "cannot cancel disbursed reward"
- T27: Bulk approve 10 rewards → all move to APPROVED

### Policy Locking
- T28: Reward record stores policyId and categoryId at calculation time
- T29: Admin changes policy → existing rewards unaffected
- T30: Achievement verified Jan 2025 with policy v1 → rewards use v1 rates even after v2 activates

### Cancellation on Rejection
- T31: Achievement VERIFIED → rewards CALCULATED → achievement REJECTED → all rewards CANCELLED
- T32: Cancellation reason stored on each reward

### Adjustment

- T34: Adjustment links via adjustmentOfId
