# R3.2 — Assessment Workspace, Score Engine & Collaboration
# ═══════════════════════════════════════════════════════════════════════════════

## Goal

Build the **core working surface** where institutions prepare for accreditation.
This is the full-fledged filing support system — workspace management, year-wise data
entry, evidence with version control, team collaboration with assignments/discussions/
sign-offs, score computation, gap analysis, and submission readiness gates.

**This + R3.1 = Minimum Viable Standalone Product.** An institution can manage their
entire NAAC/NIRF/NBA prep without needing the KRA/KPI module.

Depends on: R3.1 (framework & criteria engine)

---

## Design Decisions

1. **Assessment Workspace** = one accreditation exercise (e.g., "NAAC Cycle 5, 2024-2029")
2. **Year-wise data entry** — NAAC needs 5 years, NIRF needs 1 year. Each criterion entry stores data per year.
3. **Data source tracking** — each year-entry tagged as MANUAL, KPI_LINKED, or EXTERNAL
4. **Manual score override** — institution can override auto-computed score
5. **Evidence versioning** — multiple versions of same document, remarks per version, one marked FINAL
6. **Evidence cross-reference** — same evidence can be linked to multiple criteria
7. **Person assignment** — IQAC assigns criteria to responsible persons (system users or external by name/email)
8. **Criterion-level review workflow** — BLANK → IN_PROGRESS → COMPLETE → UNDER_REVIEW → APPROVED
9. **Threaded discussions** — comment threads per criterion entry for team deliberation
10. **Change log** — every data change tracked with optional reason (DVV defense)
11. **Section sign-off** — assigned person formally signs off their section
12. **Milestone tracking** — workspace-level deadlines and preparation milestones
13. **Submission readiness gate** — enforced checklist before freeze/submit
14. **Score snapshots** — point-in-time snapshots for progress tracking
15. **What-if simulation** — adjust scores, see live impact on grade
16. **Cross-workspace data reuse** — suggest data from other workspaces when creating new one

### Enums

```prisma
enum AssessmentStatus {
  DRAFT              // being set up
  IN_PROGRESS        // data entry ongoing
  UNDER_REVIEW       // internal review before submission
  FROZEN             // data locked, preparing to submit
  SUBMITTED          // submitted to accreditation body
  COMPLETED          // accreditation result received
  ARCHIVED           // historical
}

enum CriterionEntryStatus {
  BLANK              // no data entered yet
  IN_PROGRESS        // partially filled
  COMPLETE           // data + evidence ready
  UNDER_REVIEW       // reviewer is checking
  CHANGES_REQUESTED  // reviewer sent back
  APPROVED           // reviewed and approved
}
```

### `score-engine-service.ts` (NEW)

```typescript
// ── Score Computation ──
computeWorkspaceScores(workspaceId, tenantId): Promise<ScoringResult>
// For each leaf criterion:
//   1. Aggregate yearData (avg, sum, latest — based on criterion config)
//   2. Validate against criterion validationRules
//   3. Evaluate scoring slab → computedScore
//   4. Apply manualOverride if set → finalScore
// For parent criteria:
//   5. Roll up child scores (weighted sum using profile weights)
// For workspace:
//   6. Sum all top-level criterion scores → overallRawScore
//   7. Apply conversion formula → overallConvertedScore (CGPA)
//   8. Resolve grade band → resolvedGrade + outcome
//   9. Check threshold rules → violations

// ── What-If Simulation ──
simulateScoreChange(workspaceId, tenantId, changes: {criterionId, newScore}[]): Promise<SimulationResult>
// Returns: new overall score, new grade, delta from current, threshold impact
// Does NOT persist — read-only calculation

// ── Gap Analysis ──
getGapAnalysis(workspaceId, tenantId): Promise<GapAnalysis>
// For each criterion: currentScore, maxScore, percentage, gap to target grade
// Ranked by: biggest gap first (low-hanging fruit)
// Includes: effort estimation ("improve by X points to move from B++ to A")

// ── Snapshots ──
takeSnapshot(workspaceId, tenantId, snapshotName?, actorUserId): Promise<Result>
  // Auto-taken on freeze. Manual snapshots anytime.
listSnapshots(workspaceId, tenantId): Promise<Snapshot[]>
compareSnapshots(snapshotId1, snapshotId2): Promise<SnapshotDiff>

// ── Drift Detection (for frozen workspaces) ──
checkDrift(workspaceId, tenantId): Promise<DriftReport>
// Compare frozen values against current data source state
// Returns: {criterionId, frozenValue, currentValue, delta, recordCountDiff}
```

### Score Aggregation Rules
| Year aggregation | When to use | Example |
|---|---|---|
| AVERAGE | Default for most metrics | Avg publications over 5 years |
| SUM | Cumulative totals | Total grants received |
| LATEST | Point-in-time metrics | Current faculty count |
| MAX | Best performance | Highest pass rate |
| WEIGHTED_RECENT | Recent years matter more | 40% latest + 30% prev + 20% + 10% |

- T2: Initialize entries → creates CriterionEntry for every leaf criterion
- T3: Entry count matches leaf criterion count
- T4: Archive workspace → status=ARCHIVED

- T6: Set year data for 2024 → persists with MANUAL source
