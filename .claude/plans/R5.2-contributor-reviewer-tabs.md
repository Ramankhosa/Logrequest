# R5.2 — "My KPIs" + "My Reviews" Tabs

**Assigned to**: Opus (UI with light backend)
**Depends on**: R5.0 (scope resolver), R5.1 (shared components + dashboard shell)
**Blocks**: Nothing (can run in parallel with R5.3+)

---

## Why This Exists

These two tabs serve the most common users: contributors tracking their own KPIs and unit heads reviewing submissions. Both build on existing services (`my-kpi-service.ts`, `getMyReviewQueue()`) with minimal new backend work — primarily UI assembly using the shared component library from R5.1.

```
│ │ Dr Z         | Grant   | RECOM  | 1 day    │   │
│ └────────────────────────────────────────────┘   │
│                                                   │
│ [Click row → expands inline detail + actions]     │
│ ┌────────────────────────────────────────────┐   │
│ │ Prof X — Research Publication Q1            │   │
│ │ Target: 5 publications  Actual: 3           │   │
│ │ Evidence: [Link 1] [Link 2]                 │   │
│ │ Score: 60.0  Submitted: 22 Mar 2026         │   │
│ │                                             │   │
│ │ Note: ___________________________________   │   │
│ │ [Recommend ✓] [Send Back ↩] [Reject ✕]    │   │
│ └────────────────────────────────────────────┘   │
└──────────────────────────────────────────────────┘
```

**Data flow**:
1. Fetch from `GET /api/tenant/kra-kpi/dashboard/review-queue?periodId=X`
2. Summary counts computed client-side from the queue data
3. FilterBar for unit (if user heads multiple), state, KPI
4. DataTable sorted by waiting days descending (stalest first — UX-9)
5. Row click expands inline detail (not slide-over — keeps context)

**Expanded row shows**:
- Achievement details: KPI title, target, actual, evidence links, score
- Text input for recommendation/rejection note
- Action buttons: Recommend (green), Send Back (amber), Reject (red)
- Buttons call existing API endpoints:
  - Recommend: `POST /api/tenant/kra-kpi/achievements/{id}/recommend`
  - Verify: `POST /api/tenant/kra-kpi/achievements/{id}/verify`
  - Reject: same endpoint with `approved: false`
- After action: remove from queue, show success banner, update counts

**Stale indicator**:
- Waiting >7 days: amber warning icon + amber text
- Waiting >14 days: rose warning icon + rose text
