# R3.3 — KPI Integration & Smart Linking
# ═══════════════════════════════════════════════════════════════════════════════

## Goal

Connect the Accreditation module to the KRA/KPI module. Tenant admin maps KPI
achievements to criterion entries with configurable filters (org unit, date range,
program, state) and aggregation functions. Supports hybrid mode: some years manual,
some years auto-pulled from KPIs.

This is the **upsell for existing KRA/KPI customers** — "You already have the data,
let us auto-fill your accreditation metrics."

Optional module — standalone buyers skip this entirely.

Depends on: R3.1 + R3.2 + KRA/KPI module (R1/R2)

---

## Design Decisions

1. **Mapping = configurable query** — each CriterionKpiMapping defines which KPI to pull, with filters and aggregation
2. **Multiple KPIs per criterion** — a criterion entry can have multiple KPI mappings (e.g., "Total Research Output" = publications KPI + patents KPI + grants KPI)
3. **Filters on mapping** — orgUnit filter (CSE only for NBA), date range, achievement state (VERIFIED only), contributor role, etc.
4. **Aggregation per mapping** — SUM, AVG, COUNT, MAX, LATEST per KPI pull
5. **Cross-mapping aggregation** — when multiple KPIs map to one criterion: SUM (default), AVG, or custom formula
6. **Hybrid mode** — some years auto-linked, some manual. Year data source tag distinguishes them.
7. **Pull on demand** — no real-time sync. User clicks "Refresh from KPIs" to pull latest data.
8. **Transform formula** — optional post-aggregation formula (e.g., "value / facultyCount * 100" for per-capita)

## Schema (2 new models)

### Models

#### CriterionKpiMapping
```prisma
model CriterionKpiMapping {
  id                  String              @id @default(cuid())
  entryId             String              // which CriterionEntry
  kpiDefinitionId     String              // which KPI to pull from
  filterOrgUnitIds    String[]            // empty = all units
  filterDateFrom      DateTime?           // override workspace period
  filterDateTo        DateTime?
  filterState         String[]            // ["VERIFIED"] — default
  filterContributorRole String?           // only "Lead" achievements, etc.
  filterTags          String[]            // custom tenant tags
  aggregation         String              @default("SUM")  // SUM, AVG, COUNT, MAX, LATEST
  transformFormula    String?             // optional: "value / 100", "value * 0.5"
  isActive            Boolean             @default(true)
  createdByUserId     String
  createdAt           DateTime            @default(now())
  updatedAt           DateTime            @updatedAt
  entry               CriterionEntry      @relation(fields: [entryId], references: [id], onDelete: Cascade)
  kpiDefinition       KpiDefinition       @relation(fields: [kpiDefinitionId], references: [id])
  pullLogs            KpiPullLog[]

  @@index([entryId])
  @@index([kpiDefinitionId])
}
```

#### KpiPullLog
```prisma
model KpiPullLog {
  id              String              @id @default(cuid())
  mappingId       String
  year            Int
  pulledValue     Float?
  achievementCount Int                 // how many achievements matched filters
  transformedValue Float?             // after formula application
  pulledAt        DateTime            @default(now())
  pulledByUserId  String
  mapping         CriterionKpiMapping @relation(fields: [mappingId], references: [id], onDelete: Cascade)

  @@index([mappingId, year])
}
```

### Relations on Existing Models
- **CriterionEntry**: add `kpiMappings CriterionKpiMapping[]`
- **KpiDefinition**: add `accreditationMappings CriterionKpiMapping[]`

## Service Layer

### `kpi-accreditation-link-service.ts` (NEW)

```typescript
// ── Mapping CRUD ──
createMapping(entryId, kpiId, filters, aggregation, actorUserId): Promise<Result>
updateMapping(mappingId, data, actorUserId): Promise<Result>
deleteMapping(mappingId, actorUserId): Promise<Result>
listMappingsForEntry(entryId): Promise<Mapping[]>
listMappingsForKpi(kpiId): Promise<Mapping[]>   // reverse lookup

// ── Data Pull ──
pullKpiData(mappingId, year, actorUserId): Promise<PullResult>
// 1. Query achievements matching: kpiDefinitionId + filters (orgUnit, date, state, role)
// 2. Aggregate matched values using aggregation function
// 3. Apply transform formula if set
// 4. Write to CriterionYearData (source="KPI_LINKED", sourceRef=kpiId)
// 5. Log in KpiPullLog
// Returns: { matchedCount, rawValue, transformedValue }

pullAllMappings(workspaceId, year, actorUserId): Promise<BulkPullResult>
// Pull all KPI mappings for all entries in the workspace for a given year

refreshWorkspaceFromKpis(workspaceId, actorUserId): Promise<RefreshResult>
// Pull all mappings for all years in workspace period range

// ── Preview (dry-run) ──
previewPull(mappingId, year): Promise<PreviewResult>
// Same logic as pull, but doesn't write. Shows matched achievements + computed value.
// User reviews before confirming.

// ── Filter Builder Helpers ──
getAvailableOrgUnits(tenantId): Promise<OrgUnit[]>
getAvailableKpis(tenantId): Promise<KpiDefinition[]>
getFilterPreview(kpiId, filters): Promise<{matchedCount, sampleValues}>
```

### Aggregation Functions
| Function | Logic | Example |
|---|---|---|
| SUM | Sum of all matched achievement.actualValue | Total publications across CSE |
| AVG | Average of matched values | Average pass rate |
| COUNT | Number of matched achievements | Number of patents filed |
| MAX | Maximum value | Highest grant amount |
| LATEST | Most recent achievement's value | Current faculty count |
