---

## Why This Exists

This is the centerpiece of R5. Administrators at every level — from a VC seeing the entire institution, to a Dean comparing departments, to an HOD checking individual faculty — need to navigate the org hierarchy and see aggregated KPI performance at each level. The key interactions are: **drill down** (zoom into a child unit), **drill up** (breadcrumb back to parent), **compare** (sibling units side by side), and **compare periods** (same KPI across time).

## Task 1: Backend — New Dashboard Service Functions

### Modify: `src/lib/kra-kpi/dashboard-service.ts`

Add 4 new functions. All accept optional `scopeUnitIds` parameter for permission filtering.

### 1a. `getDrillDownNode(tenantId, periodId, unitId, scopeUnitIds?): Promise<DrillDownNode>`

```typescript
type DrillDownNode = {
  unitId: string;
  unitName: string;
  unitCode: string;
  category: string;
  level: number;
  totalAllocations: number;
  completedAllocations: number;    // VERIFIED achievements count
  completionPercent: number;
  averageScore: number;            // avg of computedScore for VERIFIED achievements
  memberCount: number;             // users assigned to this unit
  childUnitCount: number;          // direct children
  kraPerformance: {
    kraId: string;
    kraTitle: string;
    avgScore: number;
    completionPercent: number;
    totalAllocations: number;
    verifiedCount: number;
  }[];
};
```

**Logic**:
1. Get unit details from `OrgUnit`
2. Get all descendant unit IDs using `getDescendantUnitIds(tenantId, unitId, true)` from hierarchy-utils
3. If `scopeUnitIds` provided, intersect with descendant IDs
4. Query `TargetAllocation` where `assignedToUnitId IN (unitIds)` or `assignedToUser` who is in one of those units
5. Count total allocations vs allocations that have at least one VERIFIED achievement
6. Calculate average `computedScore` across VERIFIED achievements
7. Count direct children: `OrgUnit.count({ parentId: unitId })`
8. Count members: `UserOrgAssignment.count({ unitId })`
9. KRA breakdown: group by `kraDefinitionId`, compute avg score and completion per KRA

### 1b. `getCrossUnitComparison(tenantId, periodId, parentUnitId, scopeUnitIds?): Promise<CrossUnitComparison>`

```typescript
type CrossUnitComparison = {
  units: {
    unitId: string;
    unitName: string;
    unitCode: string;
    category: string;
    totalAllocations: number;
    completedAllocations: number;
    completionPercent: number;
    averageScore: number;
    kraBreakdown: { kraId: string; kraTitle: string; avgScore: number }[];
  }[];
};
```

**Logic**:
1. Get direct children of `parentUnitId`
2. For EACH child unit, compute the same metrics as `getDrillDownNode` (including descendants of that child)
3. Include KRA-level breakdown for heatmap rendering

### 1c. `getKpiPeriodComparison(tenantId, kraTitle, kpiTitle, periodIds[], scopeUnitIds?): Promise<PeriodComparisonResult>`

**⚠ Finding 8 Fix**: Match by COMPOSITE key `kraTitle + kpiTitle` (not just kpiTitle — titles alone are not unique in schema). If multiple KPIs match the same title within a period (e.g., two KRAs both have a KPI called "Publications"), return all matches with their KRA context so the UI can disambiguate.

```typescript
type PeriodComparisonResult = {
  kraTitle: string;           // added: KRA context for disambiguation
  kpiTitle: string;
  periods: {
    periodId: string;
    periodName: string;
    kpiId: string;            // added: actual KPI ID in that period
    targetTotal: number;
    achievedTotal: number;
    completionPercent: number;
    averageScore: number;
    verifiedCount: number;
    totalAllocations: number;
  }[];
  ambiguous: boolean;         // true if multiple KPIs matched in any period
};
```

**Logic**:
1. For each periodId, find `KpiDefinition` where `title = kpiTitle` (case-insensitive) AND `kraDefinition.title = kraTitle` (case-insensitive)
2. If no exact KRA+KPI match, fall back to title-only match but set `ambiguous: true`
3. For each matched KPI, aggregate allocations and achievements
4. If `scopeUnitIds` provided, filter allocations using `buildEffectiveUnitFilter`
5. Return array of per-period metrics

**Future improvement**: Add `sourceKpiId` column to `KpiDefinition` in `copyKrasFromPeriod` to create a stable cross-period link. This is a schema migration so deferred to a future release.

### 1d. `getUnitMembersSummary(tenantId, periodId, unitId, scopeUnitIds?): Promise<UnitMemberSummary[]>`

```typescript
type UnitMemberSummary = {
  userId: string;
  userName: string;
  totalAllocations: number;
  completedAllocations: number;
  overallScore: number;
  overdueCount: number;
};
```

**Logic**:
1. Get users assigned to `unitId` from `UserOrgAssignment` (published version)
2. For each user, count allocations in this period, count verified achievements, compute weighted score
3. Count overdue: allocations past deadline without verified achievement
