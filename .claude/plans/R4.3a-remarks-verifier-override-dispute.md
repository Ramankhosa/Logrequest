# R4.3a — Remarks, Verifier Credit Override & Contributor Dispute
# ═══════════════════════════════════════════════════════════════════════════════

## Goal

Add three small but critical features that were identified during R4.1c review:
1. **Applicant Remarks** — free-text field for special circumstances on achievements
2. **Verifier Credit Override** — final approver can adjust system-calculated credits
3. **Contributor Dispute** — contributor can formally flag disagreement with credit/inclusion

These are low-complexity, high-impact additions. No new services needed — all changes
extend existing models and service functions.

Depends on: R4.1c (AchievementContributor, credit calculation)

---

## Locked Decisions

| # | Decision |
|---|----------|
| D1 | `remarks` is a free-text field on Achievement — applicant-facing, visible to reviewers |
| D2 | Verifier credit override stores: who overrode, original values, reason (mandatory) |
| D3 | Override is ONLY available to the **final verifier** at verification time — not recommenders |
| D4 | Override creates an audit trail — original credits preserved in `creditOverrideSnapshot` |
| D5 | After override, inline shadow fields (Achievement.creditPercent) sync to reporter's new value |
| D6 | Dispute is a lightweight flag on AchievementContributor — not a separate workflow |
| D7 | Dispute can only be raised on VERIFIED achievements (post-approval) |
| D8 | Disputed achievements appear in admin review queue with a badge |
| D9 | Dispute resolution is manual — admin/verifier updates contributor record and clears flag |
| D10 | Remarks field is editable in DRAFT and REJECTED states only (same as other achievement fields) |

### 2. `achievement-service.ts` — verifyAchievement

**Add optional credit overrides to verify input:**

```typescript
// Extended signature:
export async function verifyAchievement(
  achievementId: string,
  tenantId: string,
  approved: boolean,
  note: string | null,
  actorUserId: string,
  actorRole: string,
  creditOverrides?: Array<{
    contributorId: string;
    newCreditPercent: number;
  }>,
): Promise<KraKpiActionResult>
```

**Override logic (inside verifyAchievement, after existing approval logic):**

```typescript
if (approved && creditOverrides && creditOverrides.length > 0) {
  // 1. Validate: all contributorIds belong to this achievement
  const existingContribs = await prisma.achievementContributor.findMany({
    where: { achievementId },
  });
  const existingMap = new Map(existingContribs.map(c => [c.id, c]));

  for (const override of creditOverrides) {
    if (!existingMap.has(override.contributorId)) {
      return { status: "error", message: "Invalid contributor ID in override", code: "INVALID_OVERRIDE" };
    }
    if (override.newCreditPercent < 0 || override.newCreditPercent > 100) {
      return { status: "error", message: "Credit must be 0-100", code: "INVALID_CREDIT_VALUE" };
    }
  }

  // 2. Require reason
  if (!note) {
    return { status: "error", message: "Override reason is mandatory", code: "OVERRIDE_REASON_REQUIRED" };
  }

  // 3. Build snapshot
  const snapshot = existingContribs.map(c => ({
    contributorId: c.id,
    userId: c.userId,
    originalCredit: c.creditPercent,
    newCredit: creditOverrides.find(o => o.contributorId === c.id)?.newCreditPercent ?? c.creditPercent,
  }));

  // 4. Update each overridden contributor
  for (const override of creditOverrides) {
    const original = existingMap.get(override.contributorId)!;
    await prisma.achievementContributor.update({
      where: { id: override.contributorId },
      data: {
        originalCreditPercent: original.creditPercent,
        creditPercent: override.newCreditPercent,
        creditOverriddenBy: actorUserId,
        creditOverrideReason: note,
        creditOverriddenAt: new Date(),
      },
    });
  }

  // 5. Update achievement-level override metadata
  await prisma.achievement.update({
    where: { id: achievementId },
    data: {
      creditOverrideSnapshot: snapshot,
      creditOverriddenBy: actorUserId,
      creditOverrideReason: note,
    },
  });

  // 6. Re-sync inline shadow fields for reporter
  const reporterContrib = existingContribs.find(c => c.userId === achievement.reportedByUserId);
  if (reporterContrib) {
    const overrideForReporter = creditOverrides.find(o => o.contributorId === reporterContrib.id);
    if (overrideForReporter) {
      await prisma.achievement.update({
        where: { id: achievementId },
        data: { creditPercent: overrideForReporter.newCreditPercent },
      });
    }
  }
}
```

### 3. `achievement-contributor-service.ts` — add dispute functions

**New exports:**

```typescript
export async function raiseDispute(
  contributorId: string,
  tenantId: string,
  note: string,
  actorUserId: string,
): Promise<KraKpiActionResult> {
  // 1. Load contributor + achievement
  const contrib = await prisma.achievementContributor.findUnique({
    where: { id: contributorId },
    include: { achievement: true },
  });
  if (!contrib) return { status: "error", code: "CONTRIBUTOR_NOT_FOUND" };

  // 2. Must be the contributor themselves
  if (contrib.userId !== actorUserId) {
    return { status: "error", code: "PERMISSION_DENIED", message: "Only the contributor can raise a dispute" };
  }

  // 3. Achievement must be VERIFIED
  if (contrib.achievement.state !== "VERIFIED") {
    return { status: "error", code: "INVALID_STATE", message: "Disputes only allowed on verified achievements" };
  }

  // 4. Already disputed?
  if (contrib.disputeStatus === "DISPUTED") {
    return { status: "error", code: "ALREADY_DISPUTED" };
  }

  // 5. Set dispute
  await prisma.achievementContributor.update({
    where: { id: contributorId },
    data: {
      disputeStatus: "DISPUTED",
      disputeNote: note,
      disputedAt: new Date(),
    },
  });

  // 6. Notify admin/verifier
  await createNotification(
    tenantId,
    contrib.achievement.reportedByUserId, // notify reporter
    "CONTRIBUTOR_DISPUTE_RAISED",
    "Contributor dispute raised",
    `A contributor has disputed their credit on "${contrib.achievement.title}"`,
    "Achievement",
    contrib.achievementId,
    "/my-kpis",
  );

  return { status: "success", id: contributorId };
}

export async function resolveDispute(
  contributorId: string,
  tenantId: string,
  resolutionNote: string,
  newCreditPercent?: number, // optional adjustment
  actorUserId: string,
  actorRole: string,
): Promise<KraKpiActionResult> {
  // 1. Must be admin/owner
  if (!["TENANT_ADMIN", "TENANT_OWNER"].includes(actorRole)) {
    return { status: "error", code: "PERMISSION_DENIED" };
  }

  // 2. Load + validate
  const contrib = await prisma.achievementContributor.findUnique({ where: { id: contributorId } });
  if (!contrib || contrib.disputeStatus !== "DISPUTED") {
    return { status: "error", code: "NOT_DISPUTED" };
  }

  // 3. Update
  const updateData: any = {
    disputeStatus: "RESOLVED",
    disputeResolvedBy: actorUserId,
    disputeResolutionNote: resolutionNote,
    disputeResolvedAt: new Date(),
  };

  if (newCreditPercent !== undefined) {
    updateData.originalCreditPercent = contrib.creditPercent;
    updateData.creditPercent = newCreditPercent;
    updateData.creditOverriddenBy = actorUserId;
    updateData.creditOverrideReason = `Dispute resolution: ${resolutionNote}`;
    updateData.creditOverriddenAt = new Date();
  }

  await prisma.achievementContributor.update({
    where: { id: contributorId },
    data: updateData,
  });

  return { status: "success", id: contributorId };
}
```

## Notification Events (from R4.1c contributor context)

These use the EXISTING notification service — no new service needed:

| Event | Recipients | Type Code |
|---|---|---|
| Added as contributor | The added user | `CONTRIBUTOR_ADDED` |
| Removed as contributor | The removed user | `CONTRIBUTOR_REMOVED` |
| Achievement submitted for review | Unit head / verifier | `ACHIEVEMENT_SUBMITTED` |
| Achievement verified/approved | All contributors | `ACHIEVEMENT_APPROVED` |
| Achievement rejected | Reporter + all contributors | `ACHIEVEMENT_REJECTED` |
| Credit overridden by verifier | Affected contributors | `CREDIT_OVERRIDDEN` |
| Dispute raised | Reporter + admin | `CONTRIBUTOR_DISPUTE_RAISED` |
| Dispute resolved | The disputing contributor | `CONTRIBUTOR_DISPUTE_RESOLVED` |
| Duplicate detected on submit | Reporter (warning) | `DUPLICATE_DETECTED` |

**Implementation:** Add `createNotification()` calls at the appropriate points in:
- `achievement-contributor-service.ts` → setAchievementContributors (add/remove)
- `achievement-service.ts` → submitForVerification, verifyAchievement
- `duplicate-detection-service.ts` → after runDuplicateDetection finds matches
- New dispute functions (above)
