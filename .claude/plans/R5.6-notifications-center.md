# R5.6 — Notification Center (Full Page + Bell Enhancement)

**Assigned to**: Opus (UI)
**Depends on**: R5.1 (shared components — DataTable, FilterBar)
**Blocks**: Nothing (can run in parallel with any module)

---

## Why This Exists

Notifications are being generated (achievement state changes, reward transitions) but users can only see them via the existing bell dropdown which shows the last 20 items without filtering. Users need a full-page notification center with filters, pagination, and grouped views. This is the simplest R5 module.

## Task 2: Notification Center Panel

### 2a. Create: `src/components/dashboard/notifications/notification-panel.tsx`

```typescript
type NotificationPanelProps = {};
```

Fetches from existing `GET /api/tenant/notifications` (enhanced with filters).

**Layout**:
```
┌──────────────────────────────────────────────────┐
│ Notifications                    [Mark all read] │
│                                                   │
│ Filters: [Type ▼] [○ All ● Unread] [Date range] │
│ Active: [Rewards ✕] [Unread only ✕]             │
│                                                   │
│ Today                                             │
│ ┌────────────────────────────────────────────┐   │
│ │ 🔔 Reward Released                        │   │
│ │ Your reward of ₹5,000 for "Publication     │   │
│ │ Q1" has been released.        2 hours ago  │   │
│ │                                    [→]     │   │
│ └────────────────────────────────────────────┘   │
│ ┌────────────────────────────────────────────┐   │
│ │ ✓ Achievement Verified                     │   │
│ │ Your "Patent Filing" achievement has been   │   │
│ │ verified by Dr. Smith.        5 hours ago  │   │
│ │                                    [→]     │   │
│ └────────────────────────────────────────────┘   │
│                                                   │
│ Yesterday                                         │
│ ┌────────────────────────────────────────────┐   │
│ │ ⚠ Achievement Rejected                     │   │
│ │ Your "Grant Application" was sent back      │   │
│ │ for revision. Reason: ...     1 day ago    │   │
│ │                                    [→]     │   │
│ └────────────────────────────────────────────┘   │
│                                                   │
│ Showing 1-20 of 45      [← Prev] [Next →]       │
└──────────────────────────────────────────────────┘
```

**Features**:
- **Grouped by date**: Today, Yesterday, This Week, Older (using `date-fns` for formatting)
- **Filter by type**: dropdown with notification type options (Achievement, Reward, KPI, System)
- **Read/Unread toggle**: radio buttons (All / Unread only)
- **Date range filter**: optional from/to date inputs
- **Mark all as read**: button at top right, calls existing `markAllAsRead()`
- **Pagination**: 20 per page, Previous/Next buttons
- **Click notification**: navigates to `linkUrl` if present, marks as read
- **Unread indicator**: unread items have a blue left border (4px) and slightly different background
- **Arrow icon** (→) on each item navigates to the related entity

**Notification type icon mapping**:
| Type contains | Icon | Tone |
|--------------|------|------|
| `VERIFIED` or `APPROVED` or `RELEASED` | CheckCircle | teal |
| `SUBMITTED` or `RECOMMENDED` or `PENDING` | Clock | blue |
| `REJECTED` or `REVOKED` | XCircle | rose |
| `REWARD` | Gift | amber |
| `ALLOCATED` or `ASSIGNED` | UserPlus | blue |
| Default | Bell | slate |

**Relative time**: Use `date-fns formatDistanceToNow` ("2 hours ago", "1 day ago")

### 2b. Modify API: `src/app/api/tenant/notifications/route.ts`

Add query params to existing GET endpoint:
- `typeFilter`: comma-separated notification types to include
- `unreadOnly`: boolean flag
- `from`, `to`: date range
- `page`, `limit`: pagination (default limit=20)

Modify the service call to pass these filters to `getNotifications()`.
