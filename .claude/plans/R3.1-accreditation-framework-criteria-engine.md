# R3.1 — Accreditation Framework & Criteria Engine
# ═══════════════════════════════════════════════════════════════════════════════

## Goal

Build the **foundation layer** for the standalone Accreditation Management System.
Super admin manages global accreditation bodies (NAAC, NIRF, NBA, QS) with versioned
criteria trees, institution-type profiles with weight overrides, scoring slabs, and
grade bands. Tenant admin can also create custom/internal frameworks.

This is the data catalog that everything else reads from — R3.2, R3.3, R3.4 all depend on it.

---

## Design Decisions

1. **Recursive criterion tree** — self-referencing `parentId` handles 1-3 levels of nesting (QS is flat, NAAC goes 3 deep)
2. **Body versioning** — NAAC RAF 2017 vs NAAC 2024 are separate versions of the same body. Old workspaces keep old version.
3. **Institution-type profiles** — Same body has different weights for University vs Affiliated vs Autonomous. Profile = weight override set.
4. **Scoring slabs** — Per-criterion scoring ranges (e.g., "≥20 publications = 30/30, 10-19 = 20/30"). Covers NAAC + NBA. NIRF/QS use external scores.
5. **Grade bands** — Optional per body (NAAC has A++ to D, NBA has Accredited/Provisional/Not, NIRF/QS have none)
6. **Threshold rules** — Per-criterion minimums (NBA: 60% per criterion for full accreditation) and total minimums
7. **Pre-seeded data** — Ship with NAAC RAF 2017, NIRF 2025, NBA Tier-II, QS 2025 via seed migration
8. **Hybrid scope** — GLOBAL bodies are read-only for tenants. TENANT bodies are fully editable by that tenant admin.

### Enums

enum AccreditationScope {
  GLOBAL           // super admin managed, visible to all tenants
  TENANT           // tenant-created custom framework
}

enum CriterionDataType {
  QUANTITATIVE     // numeric, can be auto-scored via slabs

model AccreditationBody {

#### AccreditationCriterion (recursive tree)
```prisma
model AccreditationCriterion {
  id              String              @id @default(cuid())
  versionId       String
  parentId        String?             // null = top-level criterion
  criterionCode   String              // "1", "1.1", "1.1.1", "3.2.2"
  title           String
  description     String?
  dataType        CriterionDataType   @default(QUANTITATIVE)
  maxScore        Float?              // base max score (may be overridden by profile)
  sortOrder       Int                 @default(0)
  depth           Int                 @default(0)  // 0=top, 1=sub, 2=metric
  unitOfMeasure   String?             // "count", "percentage", "ratio", "currency"
  validationRules Json?               // {min?, max?, format?, yearOverYearMaxDelta?}
  expectedEvidence Json?              // [{docType, description, isMandatory}] — pre-seeded checklist
  isLeaf          Boolean             @default(false) // only leaf nodes hold data
  isActive        Boolean             @default(true)
  createdAt       DateTime            @default(now())
  updatedAt       DateTime            @updatedAt
  version         AccreditationBodyVersion @relation(fields: [versionId], references: [id], onDelete: Cascade)
  parent          AccreditationCriterion?  @relation("CriterionTree", fields: [parentId], references: [id])
  children        AccreditationCriterion[] @relation("CriterionTree")
  scoringSlabs    AccreditationScoringSlab[]
  profileWeights  AccreditationProfileWeight[]
  thresholdRules  AccreditationThresholdRule[]
  // R3.2 will add: criterionEntries CriterionEntry[]
  // R3.3 will add: kpiMappings CriterionKpiMapping[]

  @@unique([versionId, criterionCode])
  @@index([versionId, parentId, sortOrder])
  @@index([versionId, depth])
}
```

### Validation Rules
- Body `code` unique per tenant (or per global scope)
- Version `versionCode` unique per body
- Criterion `criterionCode` unique per version
- Profile `profileCode` unique per version
- Scoring slab ranges must not overlap within a criterion
- Grade band ranges must not overlap within a version
- Only super admin can create/edit GLOBAL bodies
- Tenant admin can create TENANT bodies + view GLOBAL bodies (read-only)
- Cannot archive body/version with active assessment workspaces (R3.2 constraint, enforced later)
- Criterion tree depth max 3 levels (configurable)
- `isLeaf` must be true for criteria that have scoring slabs

## Seed Migration

Pre-seed the following frameworks with full criteria trees:

### NAAC RAF 2017
- 7 criteria, ~115 metrics (University profile)
- 3 profiles: University, Autonomous College, Affiliated College
- Grade bands: A++ (3.76-4.00) through D (≤1.50)
- Thresholds: 25% pre-qualifier on QnM

### NIRF 2025
- 5 parameters: TLR (30%), RPC (30%), GO (20%), OI (10%), PR (10%)
- Sub-parameters as depth-1 criteria
- 1 profile: Overall (category-specific deferred)
- No grade bands (pure ranking)

### NBA Tier-II (SAR 2025)
- 10 criteria, programme + institute level
- 2 profiles: Tier-I, Tier-II
- Threshold: 60% per criterion for accreditation, 45% for provisional
- Grade bands: Accredited (≥900), Provisional (≥720), Not Accredited (<600)

### QS World Rankings 2025
- 9 indicators (flat, no nesting)
- 1 profile: Universal
- No grade bands, no thresholds
